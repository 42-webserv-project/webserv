## Git Ruleset.
We added a ruleset to the main branch to avoid accidents from happening! Here are some of the key details;

**Rebase, merge, squash**

  - Even though we both prefer `rebase` we decided to include `merge` (and `squash`) because it is often easier
        and we do not need to complicate matters right now.

**Amount of Reviewers before allowed to merge**
  - This is a big one we already do technically. We need someone to look at our code before we can merge.
        Now it is also impossible to merge if a PR hasn't been approved by a reviewer.

**Cannot Review your own Pull Request**

  - Speaks for itself. Someone else needs to approve your PR.
        
**Pull request approval gets undone after new commits**

  - If someone approved your PR, but you decided to fix some things still and adding (new) commits
        the PR approval gets undone and someone will need to approve your PR again before you can merge

**Test must be passed for PR to merge**
    
  - PR must pass all the tests by our `tester`

## `Src` restructure of folders

To make our source directory more readable we thought it wise to split all modules into separate folders

Tetiana will make a new branch implementing these new structures. A full decision hasn't been decided yet
but our current view is as follows:

    i/o
        All In and Out communication, the event loop of the server, polling queing etc.

    config
        Relevant files for the configuration (parser). Tokenizer, Lexxer etc.

    http
        Relevant files considering HTTP information. Contains The Parser, Request and response.

    utils
        Utilities that help the program. App Exceptions, Logger, etc.
